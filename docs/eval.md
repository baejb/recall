# Eval 계획 — 무엇을 어떻게 채점하나

> 근거: `docs/recall_ai_prd.md` §05(품질 기준) · §06(실패 정의) · §07(평가 계획).
> 이 문서는 **지금 저장소에 있는 것**을 적는다. PRD 가 요구하는데 아직 없는 것은 §범위 밖에 남긴다.

## 왜 Eval 이 따로 있나

단위테스트는 "이 함수가 이렇게 동작한다"를 고정한다. Eval 은 **"이 정도면 합격인가"**를 고정한다.
확률적 단계(C·S2·S4·RR·A)는 케이스 하나가 틀리는 것 자체가 결함이 아니고, 반대로 전부 통과해도
커버 범위가 좁으면 의미가 없다. 그래서 케이스를 **데이터로** 두고 비율로 채점한다.

PRD §7.3 이 요구하는 것: **프롬프트를 고치면 그 단계 Eval 을 다시 돌린다**, 그리고
**🔴 케이스 1건이라도 실패하면 병합을 막는다**.

## 두 갈래로 나눈다

| | 결정론 Eval | LLM 품질 Eval |
|---|---|---|
| 대상 | M0 마스킹 · P 규칙표 · RRF 융합 · 카드 정규화 | C 유형 라우팅 · S2 추출 · S4 판정 |
| 실행 | `./gradlew test` (PR 마다 CI) | `./gradlew llmEval` (사람이 필요할 때) |
| 태그 | `release-gate`(🔴) 또는 무태그 | `llm-eval` — 기본 `test` 에서 **제외** |
| 채점 | 단정(같은 입력=같은 출력) | 정확도 임계(PRD §05 값) |
| 비용 | 0 | provider 호출 비용 |

**왜 LLM Eval 을 CI 에서 빼나** — PR 마다 돌리면 모델 출력 변동으로 진짜 회귀가 아닌 이유로
빨개진다. 그 소음이 반복되면 사람이 빨간 체크를 무시하기 시작하고, 그 순간 게이트가 죽는다.
비용도 PR 수만큼 든다. 그래서 CI 는 밀리초·무료·재현 100% 인 것만 담고, LLM Eval 은
**프롬프트를 고친 직후** 사람이 돌린다.

### 케이스를 늘리는 방법

JSON 에 한 줄 추가한다 — 코드는 고치지 않는다. 실패를 하나 발견할 때마다 케이스를 더하는 것이
PRD §7.1 이 말하는 "6개월 뒤 단단한 셋"이 되는 유일한 경로다.

**케이스는 지금 합성이다.** 실제로 겪은 대화가 아니라 만들어 넣은 것이라, 실제 사용 패턴을 대표한다는
보장이 없다. 실데이터가 생기면 합성 케이스를 교체·보강한다(그때가 이 셋의 진짜 시작이다).

> **주의: 픽스처 값은 "명백히 가짜"여야 한다.** 마스킹 케이스는 시크릿처럼 생긴 문자열을 담으므로,
> 진짜처럼 보이면 **GitHub push protection 이 푸시를 막는다**(실제로 막혔다 — Slack 토큰·웹훅 URL
> 모양이 스캐너 서명과 일치했다). 정규식이 요구하는 **모양**은 유지하면서 값에 `EXAMPLE`·`NOT-A-REAL`
> 같은 표시를 넣는다. 차단은 우회 링크로 풀 수 있지만 풀지 않는다 — 그 습관이 진짜 유출을 통과시킨다.
> AWS 처럼 공식 문서 예시값(`AKIAIOSFODNN7EXAMPLE`)이 있으면 그걸 쓴다.

## 채점 방식이 단계마다 다른 이유

- **M0 마스킹** — 두 축이다. (1) 케이스의 `secrets` 조각이 결과에 하나도 없어야 한다(🔴).
  (2) `expect` 의 플레이스홀더 종류가 맞아야 한다 — 가려지긴 했는데 종류가 어긋나면 검토 화면이
  무엇을 가렸는지 잘못 알려준다. 음성 케이스(가릴 것이 없는 입력)는 **원문이 그대로여야** 한다:
  과잉 마스킹은 원문을 못 읽게 만드는 반대 방향의 실패다. 멱등(`mask∘mask = mask`)도 케이스마다 본다.
- **P 규칙표** — 결정론이라 라벨셋이 필요 없다. 표를 고정하는 것이 Eval 이다. 특히 *구현되지 않은
  채널에 가중치를 주지 않는지* 를 본다 — 융합이 모르는 채널을 조용히 무시하므로, 그건 "설정했는데
  안 먹는" 상태가 된다. 커버리지 검사는 규칙표가 아니라 **`MemoryType.values()` 를 순회**한다:
  규칙표만 순회하면 enum 에 유형을 추가하고 `PlanContribution` 을 빠뜨려도 전부 초록이고, 빠진
  유형은 `StrategyRegistry.get` 이 런타임에 터질 때에야 드러난다(유형의 완전한 목록은 enum 자신이라
  순회해도 빠뜨릴 수 없다 — 전략 목록을 자동 수집하는 것과는 다르다).
- **S2 추출** — 필드 값을 문자열로 비교하지 않는다. 같은 사실도 표현이 매번 다르므로("메모리 한도
  초과" vs "heap 이 한도를 넘음") 일치로 채점하면 옳은 답도 틀린 것이 된다. 대신 **구조적 성질**을
  본다: `status` 열거값 · `attempts` 개수와 **실패 시도 보존**(🟠) · 에러 식별자가 시그니처·메시지에
  남았는지 · 밝혀지지 않은 원인을 지어내지 않았는지.
- **S4 판정** — 정확도와 별개로 **CONFLICT 격하 0건**을 따로 단정한다. 충돌을 약한 판정으로
  내리면 두 기록 중 하나가 조용히 덮일 수 있어서, 임계를 통과했더라도 그 자체를 실패로 본다.

## 마스킹 미커버 모양 (`masking-gaps.json`)

Eval 셋을 만들면서 발견했고 **아직 안 고친** 유출 모양이다. 케이스로 남겨 두면 고칠 때 검증 수단이
이미 있다. `MaskingGapEvalTest` 의 `@Disabled` 를 지우고 케이스를 `masking-m0.json` 으로 옮기면
커버 범위가 넓어진 기록이 diff 로 남는다.

| 모양 | 왜 지금 안 하나 |
|---|---|
| `Authorization: Basic dXNlcjpwYXNz` | Basic 은 base64(user:pass) 라 값 자체가 자격증명. Bearer 규칙이 잡지 않는다 |
| `postgresql://user:pass@host/db` | 구분자가 `:`·`@` 라 KEY=VALUE 모양이 아니다. URL 파싱 규칙이 따로 필요. 호스트에 점이 있으면(`db.internal`) 이메일 규칙이 `user:pass@host` 를 통째로 삼켜 값이 우연히 지워지는데, 그건 커버가 아니라 **오분류**다 — 검토 화면이 DB 비밀번호를 `⟨email⟩` 로 알려준다. 픽스처를 점 없는 호스트(`localhost`)로 둬서 그 우연에 가려지지 않게 했다 |
| 웹훅 URL (`hooks.slack.com/services/...`) | URL 자체가 자격증명. 호스트별 규칙이 필요하고 일반 URL 을 다 가리면 원문이 망가진다 |
| `비밀번호는 hunter2 입니다` | 구분자 없는 문장형. 값의 경계를 결정론으로 정할 수 없다("입니다"까지 가릴지) |
| 키 이름 없는 고엔트로피 문자열 | 엔트로피로 가리면 커밋 해시·에러 시그니처·UUID 까지 가려 트러블슈팅 카드가 무의미해진다 |
| 전화번호·주민번호(PII) | PRD 마스킹 범위는 자격증명 중심. PII 포함은 제품 결정이라 임의로 넓히지 않았다 |

> 이번에 **고친** 것: 한국어 키 이름(`비밀번호:`·`암호키=`·`토큰=`)과 축약 키(`db_pass=`). 원문이
> 한국어인 제품에서 영어 키 이름만 보면 "비밀번호: hunter2" 가 그대로 외부 LLM·인덱스로 나간다.

### 키 이름을 두 단으로 나눈 이유 (리뷰 피드백 반영)

첫 구현은 키 이름 목록 하나에 `token`·`토큰`·`암호` 를 함께 넣었다. 그 결과 **양방향으로 틀렸다**.

- **거짓 양성** — `최대 토큰: 4096` · `max_tokens=4096` · `암호: AES-256-GCM` 이 전부 가려졌다.
  가린 값은 버리는 설계(복원용 원문 없음)라 이건 **되돌릴 수 없는 값 손실**이다. 검토 화면에서
  시크릿이 아니라고 판단해도 그 memory 는 숫자가 빠진 채 남는다. 라벨셋에 이 방향 음성 케이스가
  없어서 게이트가 그 손실을 정상으로 굳히고 있었다.
- **거짓 음성** — 키 이름을 감싼 문자군에 한글이 없어 한글 키는 **접두만** 걸렸다.
  `토큰값:` · `암호키=` · `비밀번호 확인:` 이 그대로 통과했다. 축약 키의 `pass(?![a-z])` 는 거르는
  방향이 뒤집혀 있어 `passphrase=my-secret` 을 통과시키고 `bypass=true` · `pass_rate=0.9` 를 가렸다.

그래서 키 이름을 성격으로 나눈다.

| | 키 이름 | 판정 |
|---|---|---|
| **확정 키** | `password` `passwd` `pwd` `passphrase` `secret` `api_key` `apikey` `access_key` `client_secret` `비밀번호` `암호키` `비밀키` · 마지막 세그먼트인 `pass` | 값이 무엇이든 가린다 (`POSTGRES_PASSWORD=12345678` 포함) |
| **모호한 키** | `token` `토큰` `암호` | 값이 **12자 이상 + 글자 포함**일 때만 가린다 |

임계 12 의 근거: 이 자리에서 실제로 부딪히는 도메인 값은 짧다(`4096` · `AES-256-GCM`=11자). 자격증명은
대체로 그보다 길다. `masking-m0.json` 의 음성 케이스가 이 경계를 고정한다.

`암호키`·`비밀키` 가 확정 쪽인 이유: `키` 가 붙으면 더 이상 "암호화 방식"을 가리키는 도메인 단어가
아니라 자격증명이다. 모호한 쪽에 두면 `암호키=hunter2` 처럼 **짧은 값이 길이 가드에 걸러져 그대로
나간다**.

**남는 대가**: 모호한 키의 짧은 시크릿(`토큰: abc123`)은 통과한다. 실제 토큰은 대개 12자를 넘고
`ghp_`·`sk-`·`xox` 같은 전용 규칙이 접두로 먼저 잡으므로 감수한다 — 되돌릴 수 없는 값 손실 쪽이 더
비싸다고 봤다.

## LLM Eval 돌리는 법

```bash
# .env 의 provider 설정을 그대로 쓴다(운영과 같은 모델로 채점해야 그 점수가 의미가 있다)
set -a; . .env; set +a
cd backend && ./gradlew llmEval
```

키가 없으면 **스킵**된다(실패가 아니다). "안 돌았음"과 "회귀"를 리포트에서 구분할 수 있어야 한다.

## CI 게이트 — 아직 없다 (보류)

> **현재 상태**: 워크플로 파일은 작성돼 있지만 **저장소에 들어오지 않았다.** GitHub 이 워크플로
> 파일을 `workflow` 스코프로 따로 잠가 두는데(워크플로는 러너에서 실행되고 Secrets 에 접근하므로
> "코드 쓰기"와 분리) 지금 토큰에는 그 스코프가 없어 푸시가 거부됐다. 스코프를 넓힐지 웹 UI 로 넣을지는
> 팀 결정으로 미뤘다.
>
> **그래서 지금은 `releaseGate` 가 로컬에서만 돈다 — 아무것도 막지 못한다.** PRD §7.3 이 요구하는
> "🔴 1건 실패 시 병합 차단"은 아래 워크플로가 들어오고 branch protection 이 걸린 뒤에 성립한다.

들어올 워크플로의 내용(`.github/workflows/ci.yml`) — develop·main 으로 가는 PR 과 두 브랜치 push
에서 돈다.

- **backend**: `test` → `releaseGate`(🔴) → `spotlessCheck`. pgvector 서비스 컨테이너를 띄운다
  (소유자 격리·교차유출 게이트가 실제 스키마를 요구한다). `RECALL_SECRET_KEY` 는 **일부러 주지
  않는다** — 키 미설정 시 DB 영속을 거부하는 fail-closed 동작을 검증하는 테스트가 있다.
- **frontend**: `npm ci` → `build`(tsc 포함) → `lint` → `format:check`.

`releaseGate` 를 전체 `test` 와 따로 한 번 더 돌리는 이유: 실패했을 때 **"🔴 치명 회귀가 깨졌다"가
체크 이름으로 바로 보여야** 한다. 261개 중 하나가 빨간 것과 게이트가 빨간 것은 다른 사건이다.

## 범위 밖 (PRD 가 요구하는데 아직 없음)

- **R+W 검색 Recall@5 · MRR** — 라벨셋(질문 → 정답 memory)과 색인된 코퍼스가 함께 필요하다.
  임베딩 호출이 들어가므로 LLM Eval 쪽이고, 코퍼스를 만드는 것이 별개 작업이다.
- **RR 리랭크 nDCG@5** — 비교 질문에 순위 라벨이 필요하다.
- **A 답변 citation ≥ 0.95 · 환각 ≤ 0.02** — LLM-as-a-Judge 가 필요하다(PRD §7.2 피라미드 2층).
  근거 없는 생성 금지는 지금 `AnswerStreamerTest`(🔴, "근거 없음 → LLM 미호출")로만 막고 있다.
- **C 다차원** — `route`·`novelty`·`ts_subtype`·`entities`·confidence 축이 아직 구현되지 않았다.
  지금 Eval 은 domain 축(유형) 하나만 채점한다.
- **회귀 리포트 자동화** — PRD §7.3 의 "하락 케이스 자동 리포트". 지금은 실패 메시지에 틀린 케이스가
  나열되는 수준이다.
